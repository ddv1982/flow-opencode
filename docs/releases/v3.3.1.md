# v3.3.1

Finish the SDK log-contract fix: tool-surface logging now uses the same safe wrapper as plugin startup

The 3.2.2 release fixed the plugin-startup crash from an unbound generated SDK `app.log` method and the wrong top-level payload shape. A second, quieter copy of the same integration mistake remained in `createTools`: it called `ctx.client.app.log` directly with `{ level, message }` instead of `{ body: { service, level, message } }`. Because that call was still made through `app`, it did not reproduce the original `_client` crash, but it did violate the host log contract and the SDK-shaped test fake recorded it as an `undefined` body.

This release collapses the adapter logging paths into one helper. `createFlowLog` now lives beside the OpenCode adapter and is used by both `plugin.ts` and `tools.ts`; host logging remains fail-silent and non-authoritative, the SDK method is invoked through the app object, and every entry uses the same body envelope with the Flow service name. The duplicate top-level logger in `tools.ts` is removed.

The regression coverage now checks the second log path directly. Both the source-level plugin-surface test and the built-dist smoke test assert that "Creating Flow tool surface." arrives as a body-shaped SDK log entry and that no undefined log body was accepted. The release keeps the 3.3.0 product surface unchanged: no commands, tools, schemas, state paths, synced skills, or workflow rules change.

Constraint: Host logging is best-effort adapter telemetry only; it must never be a plugin-load dependency
Constraint: Every OpenCode SDK log call must use the same `{ body: { service, level, message } }` envelope
Rejected: Keeping a separate tool-surface logger | two host-contract implementations already drifted once, and the second one was not covered by the original fix
Rejected: Removing the tool-surface log only | it avoids this instance but leaves no shared contract for update notices and future adapter logs
Confidence: high
Scope-risk: low
Reversibility: clean — one helper module and two callers
Directive: When fixing a host-interface contract, search for sibling call sites and assert each observable path, not just the failing one
