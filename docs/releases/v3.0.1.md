# v3.0.1

File-based discovery for slash commands and the reviewer agent

OpenCode did not surface the nine `/flow-*` slash commands or the `flow-reviewer` agent when they were injected only through the plugin config hook, leaving 3.0.0 installs without a working command surface. Plugin startup now also syncs them as real files into OpenCode's normal discovery paths: command markdown to `~/.config/opencode/commands/<name>.md` and the reviewer agent to `~/.config/opencode/agents/flow-reviewer.md`. Both are rendered from the same `FLOW_CORE_COMMANDS`/`FLOW_CORE_AGENTS` definitions the config hook injects (now hoisted to `src/config-shared.ts`), so the two surfaces share one source of truth and cannot drift.

The sync extends the established skill ownership model to single files: each synced file carries a sidecar `.{name}.flow-version` marker recording the plugin version and a content sha256; files without a Flow marker are never touched (a same-named user command stays untouched as `skipped_foreign`); a user-edited Flow-owned file is backed up next to itself (`<name>.md.backup`) before replacement. `bunx opencode-plugin-flow uninstall` removes pristine Flow-owned command/agent files plus their markers and backups, keeps user-edited ones, and dry-run mutates nothing. The `/flow-doctor` install check now warns when the synced command/agent surface is missing or stale, with restart-and-permissions remediation.

Constraint: Command names and templates are unchanged — this release changes where they are discovered from, not what they do
Constraint: The config hook injection stays in place alongside the synced files; revisit the duplication when the v2 compat stubs are removed in v3.1
Rejected: Shipping command/agent markdown as static package files copied verbatim | rendering from the shared config definitions keeps the config hook and the file surface provably identical
Confidence: high
Scope-risk: low
Reversibility: clean — uninstall removes the synced files; deleting them by hand degrades to the 3.0.0 behavior
Directive: Anything synced into the user's home must carry a Flow ownership marker, never touch unmarked files, and back up user edits before replacing them
Tested: `bun run check` (typecheck, lint, build, full test suite incl. new command/agent sync + uninstall + dry-run tests, npm-tarball install smoke asserting command/agent file sync and uninstall cleanup, bundle sanity); architecture seams gate
Not-tested: Live OpenCode UI slash-command discovery after a real npm upgrade
