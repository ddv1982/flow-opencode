# v3.1.0

Only the v3 surface remains: five commands, seven tools, no v2 leftovers

This release completes the v3 consolidation by removing everything that existed only for the v2 → v3 transition or duplicated the skills-first surface. The command surface trims from nine to five — `/flow-auto`, `/flow-plan`, `/flow-run`, `/flow-review`, `/flow-status` — keeping exactly the commands that load a skill plus the universal status entry point. The retired four (`/flow-doctor`, `/flow-history`, `/flow-session`, `/flow-reset`) were each a thin wrapper over a single tool call that a plain request handles identically, and `/flow-doctor` returned the same `flow_status` view as `/flow-status`.

Retirement is cleanup-aware, not just deletion: `RETIRED_FLOW_COMMANDS` drives a startup-sync pass that removes the Flow-owned files a 3.0.x install synced for the retired names (marker present, content hash matching — user-edited copies stay untouched), and uninstall does the same. This closes the gap where dropping a name from `FLOW_CORE_COMMANDS` would have stranded its synced file in `~/.config/opencode/commands/` forever; the rule is now codified in the maintainer contract.

The 15 v2 tool-name redirect stubs are removed exactly on the schedule the 3.0.0 notes committed to — the seven canonical tools are the entire registered surface, asserted as such by tests, the install smoke, and bundle sanity (extra-tool count must be zero). Runtime next-step hints that used to name retired commands now name the tool calls the skills teach (`flow_feature_complete reset <id>`, `flow_session history`, `flow_session activate <id>`); the five surviving commands are still suggested as slash commands.

Constraint: Session schema stays v1 — v2-created `.flow/**` sessions still resume unchanged (fixture-tested)
Constraint: A command earns a slot only if it loads a skill or is the status entry point; single-tool wrappers belong to plain conversation
Rejected: Keeping the retired commands as one-line redirect files for another cycle | the package is days old with one known consumer; redirect files would outnumber real users
Rejected: Removing names from FLOW_CORE_COMMANDS without install cleanup | stranded marker-owned files would shadow the trimmed surface on every existing install
Confidence: high
Scope-risk: low
Reversibility: clean — re-adding a command to FLOW_CORE_COMMANDS re-syncs it on the next startup
