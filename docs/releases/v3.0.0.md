# v3.0.0

Skills-first inversion: hand-authored skills drive the workflow, the plugin becomes a thin state backend

Flow 3.0.0 completes Phases 2–4 of `docs/plans/skills-first-overhaul-2026-06-12.md` in one breaking release. The architecture inverts: four hand-authored skills (`flow`, `flow-plan`, `flow-run`, `flow-review`, each with `references/` rubrics, worked plan examples, and a recovery playbook keyed to the runtime's real error codes) are now the primary instruction surface, checked into the repo, synced at startup under marker-file ownership, user-editable, and per-project overridable. The plugin keeps only what skills cannot guarantee: atomic, locked, path-safe `.flow/**` persistence at schema v1, zod validation at the SDK boundary, four hard invariants, the compaction hook, and a `flow_status` that returns state plus a computed next step.

The tool surface consolidates 18 → 7 canonical tools (`flow_status`, `flow_plan_save`, `flow_plan_approve`, `flow_run_start`, `flow_feature_complete`, `flow_review_record`, `flow_session`). The 15 retired v2 names remain registered for one minor cycle as hidden redirect stubs: calling one returns the standard error envelope with a `replacement` field and a one-line usage hint for the new tool, so resumed v2 sessions and old transcripts degrade gracefully instead of failing on an unknown tool. Agents collapse 6 → 1 (`flow-reviewer`, read-only via native per-agent permissions); the 9 command names are stable and are now thin pointers into skills (largest template under 300 characters, enforced by test). All generated prompt/skill/contract projections, mode contracts, capture scripts, parity tests, stack-standards profiling, the review scope/coverage accounting layers, and the `flow-auto` coordination lane are deleted.

The hard invariants are runtime-enforced and covered by direct tests: no feature completion without recorded validation evidence; no closing a session as `completed` while planned features are below the plan's completion target (structured `unfinished_features` error listing the unfinished ids); no mutating an approved plan without explicit reset; strict review policy requires a recorded reviewer decision. A malformed persisted session id degrades to a failing `session_artifacts` readiness check instead of crashing `flow_status`.

Quality reinvestment starts in the same release: a tool-name-coverage test asserts every canonical tool appears in the skill set, and a new manual golden-transcript eval lane (`bun run evals:golden`, five scenarios) drives `opencode run` headless against fixture repos and asserts outcomes from the persisted `.flow/**` state — model-key gated, never part of `check`.
