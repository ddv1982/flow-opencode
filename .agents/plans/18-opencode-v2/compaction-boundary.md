# Compaction boundary synthesis

Base A is selected. The parent read both packages in full. Parent rubric scores were A 15 and B 9. The independent Grok cross-judge scored A 14 and B 10 and selected the same base. These are design judgments on six criteria, not test results. The cross-judge report and both unchanged candidates remain in their original directories.

The source-state census and exact native reload pair reject the premise that native summary completion requires a live execution origin. A single input ledger owns historical source classification, private readiness, local input reservations, and the admission frontier. A compaction boundary owns native proof and the decision between summary-only permission and continuation. Lifecycle retains execution and policy side effects. No second transcript join, copied admission-id registry, or public lease inspection is introduced.

Use A's module and deletion plan. Move existing real candidates, accepted real origins, and private host binding into the existing admission knowledge owner. Keep InputOrigin and its revocation semantics. Historical evidence outside that owner is a discriminated ordinary or automatic fact, without a positive origin. Any originally non-null authority is historical automatic classification, including automatic=false inputs. Do not turn arbitrary errors into ordinary history. Unknown marked history after reload can summarize but cannot recover a token or satisfy checkpoint execution.

Grafts and precise requirements:

1. Reserve the local input frontier synchronously at command execute and synthetic entry, before session.get or any other await. Real prompt observation uses that same owner. The private registration links to its reservation and cannot bypass a later frontier. A failed or superseded reservation grants nothing. Interrupt advances execution lifetime and invalidates old scopes, but does not reserve a new input frontier. This is why a new ordinary manual summary after interruption can read old history without inventing a new input.
2. A scope captures exact input/lineage, lifecycle lifetime, and the local frontier. Capture rejects an old consumed source that does not cover the already reserved frontier. Every async boundary checks that same scope. New real, command, or synthetic reservations invalidate it, including same-epoch private work. Repeated callbacks for one unchanged input do not invent a new admission.
3. Scope cancellation has its own wake-up promise, separate from admission.ready. Lifetime, frontier, unload, and stream loss reject stale scope waits even when ready never settles. They do not reject a fresh admission's ready promise and do not call revoke on a fresh owner. Old finally removes only its own pending slot. A stale slot must not exclude a replacement operation before its old underlying request settles.
4. All pending private admissions wait for exact readiness before positive authority or source ownership checks. Do not inspect private lease.messageId, add an accessor for it, use current captureAuthority as a pending owner, or gate waiting on a partial-activation Boolean. Match the exact native receipt and payload under the existing admission policy. Readiness alone does not freeze a primary or grant tools.
5. One compaction parser proves exact running control, explicit reason auto/manual, full consumed/native prefix, and actual delivery. If admission readiness introduces another await after the first proof, reread and require the same native control/reason/prefix. The hook has no original control-id argument. Preserve the stated limit about correlation to an unread replaced control rather than inventing a field.
6. Manual summary of unknown or retired ordinary history is a summary-only result with no InputOrigin, authority, execution epoch, recovery renewal, guidance, primary, assistant binding, or tool grant. Do not copy the current host epoch into old provenance. Known automatic history, including revoked registrations/checkpoints, cannot fall back here. Current automatic manual refusal remains. Existing live ordinary auto/manual and live grantless plan/reviewer checkpoint behavior remains.
7. A continuation stores one checked fact and exactly one checkpoint origin. Repeated admit with equal host, control id, consumed ids and proved attributes reuses that fact and the same origin object. Completed context and retry return that object. Do not allocate compactedInputOrigin on every pure proof and compare the new object to the stored object.
8. Keep B's minimal summary-permit fence and dead-source projections. Keep classification/disposition exhaustive and pure inside the existing knowledge boundary when possible. Do not copy B's unavailable snapshot inputs, private messageBound, incomplete permission table, five public functions, or origin-identity reuse rule.
9. Keep execution failure cleanup tied to the exact still-live source. A scope's captured current lifetime is not an execution owner. Pending context, historical summary, or stale callback cannot revoke a fresh invocation. Preserve existing negative guards, genuine active-primary overlap refusal, immutable assistant/Request binding, strict marker/delivery checks, grantless completed-close origin, and no new advice/abandonment intent.

The production caller surface stays admission capture/readiness plus compaction admit/completed. PrimaryHost in A is explanatory pseudocode, not a new production forwarding class. Delete duplicated lifecycle source lookup, real/accepted maps after migration, the missing-record manual branch, isUnattributedManualSummary, and the current-authority fallback for pending ownership in the same change. Preserve exact real prompt payload matching and automatic policy.
