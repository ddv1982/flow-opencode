# Native live evaluation host

## Problem

The live evaluation plugin installs a scoped request gate and experimental Flow
controller. The host previously treated every recovery treatment as simulation.
That selected the simulation bundle, synthetic OAuth, and simulation driver origin.

This unit connects the live entry to native host startup. The episode runner keeps
its live refusal. Native startup checks send no model prompt and establish no
qualification claim.

## Configuration

`RecoveryTreatment` distinguishes live and simulation origins. Simulation requires
its script. Live accepts an arm without a script. The simulation plugin keeps its
strict simulation schema.

The host validates the live budget, execution scope, and arm before startup. Live
mode requires an explicit provider credential policy. Both experimental origins
use a source bundle and the existing executable identity checks.

The live configuration loads one plugin entry. That entry installs its own request
gate. Simulation retains its separate scripted gate and synthetic OAuth setup.
The driver derives origin from the treatment configuration and includes credential
policy in its static identity. Runtime scope remains supplied during preparation.

## Credential handling

The live Jev arm takes its key from the selected toolchain environment. It passes
the key only to the final native server process. Fixture setup receives no Jev key.
The control arm receives none. Keys do not enter plugin options or receipts.

An inherited manager credential store contains only the selected provider. The
host remembers that filtered snapshot and filters child updates before syncing.
Other providers remain in the parent store. A malformed existing parent store
causes synchronization to fail without replacement. The existing cleanup lifecycle
retains scratch when synchronization fails.

## Design decision

Two independent sketches considered the following shapes.

| Shape | Decision |
| --- | --- |
| Extend the existing treatment type with an origin union | Selected. Reuses the current host and driver with fewer caller changes. |
| Group composition, budget, and credentials into a new execution option | Rejected. Requires migration of working simulation callers and separate scoped host and unscoped driver types. |

The independent judge preferred the first shape. The synthesis adopted the second
sketch's toolchain-only key source and final-spawn handoff. Both sketches required
explicit credential policy and a filtered synchronization snapshot. Review added
filtering of child updates and refusal to replace malformed existing stores.

Model the Domain drove the explicit origin union. Laziness Protocol kept one host
lifecycle. Separate Before Serializing Shared State assigned implementation to one
code owner. Prove It Works requires native startup evidence for both arms and
manager configurations.

## Verification boundary

Native checks use private synthetic credentials and live-format test budgets.
Their review fields are fixtures, not reviewed real prices or spending approval.
No prompt or command is dispatched. Tests check live receipts, bundle and scope
identity, zero inference reservations, and cleanup.

The existing intercepted adapter tests cover Jev assessment and reservation
ordering. The paired native simulation checks cover regression of the simulation
path. Neither establishes live provider behavior, real OAuth refresh, operational
quality, or production qualification.

Live runner admission, representative operational cases, independent review,
reviewed route costs, a new explicit campaign cap, live comparisons, qualification,
and release review remain separate work. Production profiles remain empty.
