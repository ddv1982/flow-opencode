# JEV-2 disabled-mode idle-routing diagnostic

`verify.ts` rechecks the compressed and expanded hashes, complete runtime inputs (`src/`, `skills/`, `package.json`, and `bun.lock`) at both commits, phase ancestry, route counts, current-candidate source identity, and p95 arithmetic. The baseline precedes the JEV-2 introduction commit `0192ede787239205f14deb16a58643ca2896d09e`; the head contains it and the retained `auto-drive.ts` hashes differ. This fixed-input probe compares `AutoDriveCoordinator.onIdle` at pre-JEV-2 trunk `c9813f9a87b9b7438671658cfd523adcd89f3098` and current stacked runtime at `f798dc5b1c0c4ac86f3269068346a47b699f8b2b`. It warms each process, then times 1,500 calls per route with setup outside the timed interval. Both runs use the same five projections: no lease, ready continuation, blocked handback, a blocked `await-user-direction` recovery checkpoint, and inactive. The head receives a real inactive `RecoveryController` with a provider spy; the base has no recovery controller. A fetch guard rejects direct fetches during the replay. All route/read/prompt counts match, the head records 1,500 inactive-controller proposal lookups at the recovery checkpoint while the trunk records none, and both provider and fetch counters are zero. The lookup-count wrapper is included in the timed head route.

The nearest-rank p95 increase is at most 0.160 microseconds across the five routes, below the proposed 5 ms disabled-mode limit in this in-memory replay. The head's process RSS after imports is 43.48 MiB versus 28.62 MiB at the base; after the probe it is 68.11 versus 59.97 MiB. These snapshots include module loading and process variation; source-identity hashing ran after the reported RSS and timing checkpoints. Both raw arms record the same hashed host identity, CPU model/count, kernel release, and filesystem device ids. See `receipt.json` for the exact commits, fixture and artifact hashes, metrics, and limits. `baseline.json.gz` and `head.json.gz` retain every latency sample and the identical fixture digest.

Reproduce from detached worktrees at the two commits with Bun using `probe.ts <auto-drive.ts> <new-output.json> [recovery-policy.ts]`; compress a retained output with `gzip -n`. Omit the third argument for the base; pass the head's recovery policy path for the head. The output path may be any unused local path. The probe does not exercise the native OpenCode event hook, workspace status I/O, or live shadow advice. It is partial JEV-2 performance evidence, not a pass for the full performance gate or delegated qualification.
