# JEV-2 disabled-mode idle-routing diagnostic

`verify.ts` rechecks the compressed and expanded hashes, source bytes at both commits, phase ancestry, route counts, and p95 arithmetic. The baseline precedes the JEV-2 introduction commit `0192ede787239205f14deb16a58643ca2896d09e`; the head contains it and the retained `auto-drive.ts` hashes differ. This fixed-input probe compares `AutoDriveCoordinator.onIdle` at pre-JEV-2 trunk `c9813f9a87b9b7438671658cfd523adcd89f3098` and PR #107 head `4644bef8bf53b3fed2e6be3798f39c09eb2a2b5d`. It warms each process, then times 1,500 calls per route with setup outside the timed interval. Both runs use the same four projections: no lease, ready continuation, blocked handback, and inactive. The head receives a real inactive `RecoveryController` with a provider spy; the base has no recovery controller. A fetch guard rejects direct fetches during the replay. All route/read/prompt counts match and both provider and fetch counters are zero.

The nearest-rank p95 increase is at most 0.300 microseconds across the four routes, below the proposed 5 ms disabled-mode limit in this in-memory replay. The head's process RSS after imports is 45.53 MiB versus 27.81 MiB at the base; after the probe it is 70.34 versus 58.75 MiB. These snapshots include module loading and process variation.
